# MCP Tools and `_meta` Options

How SEMOSS builds MCP tool definitions, which `_meta` keys a tool author controls, and how each key behaves at runtime in `RunAgent` and `AskRoom`. Line references are to the source at the time of writing; follow the linked classes when they drift.

## Where tools come from

Every MCP tool is a JSON object in a `tools` array. The runtime merges tools from these sources:

| Source | File | Generated by | Author controls `_meta` through |
| --- | --- | --- | --- |
| Project Pixel MCP | `project/<Name>__<id>/app_root/version/assets/mcp/pixel_mcp.json` | `MakePixelMCP` | `getMcpToolMetadata()` on the reactor, `mcpMetadata` on `MakePixelMCP` |
| Project Python MCP | `.../assets/mcp/py_mcp.json` from `.../assets/py/mcp_driver.py` | `MakePythonMCP`, `MakeNotebookCellMCP` | `@mcp_metadata` decorator |
| Room toolbox | Room asset folder, `mcp/pixel_mcp.json` / `py_mcp.json` | `MakeRoomPixelMCP` | `mcpMetadata` on `MakeRoomPixelMCP` |
| User asset MCP | User asset file (`filePath`) | `MakeUserPixelMCP` | `mcpMetadata` on `MakeUserPixelMCP` |
| Engine MCP | Engine `assets/mcp/pixel_mcp.json` / `py_mcp.json` | `MakeEngineMCP` | `mcpMetadata` on `MakeEngineMCP` (execution and UI only) |
| Remote MCP | External server | None | None; the platform overwrites execution and UI |
| Platform agent tools | Java handlers | None | None; fixed in code |
| `RunAgent` explicit tools | `paramValues.tools` | Caller | Whatever the caller sends |

A room collects tools from its own toolbox, `options.mcp`, and its workspace (legacy workspace resources plus `CONFIG_JSON.mcps`) in [Room.getAllToolsJsonForRoom](../../src/prerna/engine/impl/model/Room.java). Engine and project files are read through [InternalMCP](../../src/prerna/engine/impl/InternalMCP.java). Only the `tools` array is read; a file-level `_meta` is ignored.

## Tool shape

```json
{
  "name": "RunPolicy",
  "title": "Run Policy",
  "description": "Runs the policy check against a document.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "docId": { "type": "string", "description": "Document id" },
      "strict": { "type": "boolean", "default": false }
    },
    "required": ["docId"]
  },
  "_meta": {
    "SMSS_MCP_EXECUTION": "ask",
    "SMSS_MCP_DEFERRED": true,
    "SMSS_MCP_UI": { "displayLocation": "sidebar", "loadingMessage": "Running policy..." },
    "SMSS_FUNCTION_NAME": "RunPolicy",
    "SMSS_MCP_GENERATOR": "MakePixelMCP"
  }
}
```

| Field | Use |
| --- | --- |
| `name` | Required. Prefixed with the engine id (and possibly truncated) before it reaches the model; the room keeps a reverse lookup. |
| `title` | Display title for tool cards and approvals. Also scored by `SearchTools`. |
| `description` | Sent to the model. `SearchTools` returns the first 400 characters. |
| `inputSchema.properties.*.default` / `const` | Filled into arguments the model omitted ([MCPUtility.applyMissingArgumentDefaults](../../src/prerna/reactor/agent/mcp/MCPUtility.java)). |

## `_meta` keys an author sets

| Key | Type and values | Generated default | Effect |
| --- | --- | --- | --- |
| `SMSS_MCP_EXECUTION` | `"auto"`, `"ask"`, `"yesno"`, `"disabled"` (lowercase) | Pixel: `auto`. Python: `ask`. Engine: `auto`. | `ask` and `yesno` both pause for user approval (the harness treats them identically); `yesno` only differs in how the frontend presents the decision. `disabled` hides the tool from the model. |
| `SMSS_MCP_DEFERRED` | JSON boolean `true` | Absent | Hides the schema in `RunAgent` until the agent loads it with `SearchTools` / `LoadTools`. |
| `SMSS_MCP_UI` | Object, see below | Pixel reactors: `{ "displayLocation": "sidebar" }` | Frontend hints for the tool view. |
| `SMSS_FUNCTION_NAME` | String | Stamped with the reactor or function name | The function `InternalMCP` executes. Set by hand only to alias a tool to a differently named function. |

Constants live in [MCPUtility](../../src/prerna/reactor/agent/mcp/MCPUtility.java).

### `SMSS_MCP_EXECUTION`

- Values come from `MCPUtility.MCPExecution`. The runtime treats a missing or unknown value as `ask` when it builds tool-call metadata (`getValidMcpExecution`), so a hand-written tool with no `_meta` asks.
- `yesno` pauses the harness exactly like `ask` (`MCPUtility.isAskLikeExecution`, used by `HarnessToolExecutor` and `SemossAgentHarness`); the two differ only in the approval UI the frontend renders.
- The `disabled` filter is an exact, case-sensitive match (`Room.getToolJson`, `DeferredAgentTools.isDisabled`, `PlatformAgentTools`). `"Disabled"` is **not** hidden.
- `disabled` only hides the tool from the model. `GetMCPTools` still returns it, and `RunMCPTool`, `AddToolExecution`, and the approval handler do not check it. It is not an access control.
- Remote MCP tools are always `auto`; [RemoteMCP](../../src/prerna/engine/impl/RemoteMCP.java) overwrites the value.

### `SMSS_MCP_DEFERRED`

Deferral keeps rarely used tool schemas out of the prompt. It is honored only by the native `RunAgent` harness:

1. `SemossAgentHarness` sets `DeferredAgentTools.RUN_AGENT_PARAM` on each model call and adds `SearchTools` and `LoadTools` plus a short prompt paragraph.
2. `Room.appendToolsToParams` sees the flag and passes the full tool list through `DeferredAgentTools.filterForModel`. Eager tools are sent in a stable order, followed by deferred tools that were loaded, in load order.
3. `SearchTools(query, limit)` scores deferred tools by keyword (name and title count 3, description counts 1) and returns IDs.
4. `LoadTools(toolIds)` appends IDs to room option `loadedDeferredTools` and persists them. Full schemas appear on the next model call and stay loaded for the room across later runs.

Details:

- The value must be the boolean `true` (`Boolean.TRUE.equals`). The string `"true"` is ignored at runtime and rejected by `MakePixelMCP`.
- Tool IDs are `mcp:<engineId>:<originalToolName>` for MCP tools and `default:<name>` for platform and explicit tools. IDs survive provider-specific name aliasing.
- A tool that is both `disabled` and deferred is excluded, not deferred.
- Subagent rooms start with nothing loaded (`AgentSubAgentRegistry` strips `loadedDeferredTools`).
- Deferral applies to every source in the `RunAgent` tool list: room toolbox, `options.mcp`, workspace MCPs, platform tools, and explicit `paramValues.tools`.
- Plain `AskRoom` / `Room.ask` without the harness sends every non-disabled tool eagerly, deferred or not. External harnesses (`claude_code`, etc.) do not apply deferral.
- The executor does not refuse a call to a deferred tool that was never loaded. Deferral controls what the model sees, not what can run.
- Platform tools `InspectPptx` and `MultiEdit` are deferred by default ([PlatformAgentTools](../../src/prerna/reactor/agent/runtime/PlatformAgentTools.java)). When `AGENT_DEFAULT_TOOLS_MCP_ID` points at an override MCP, that MCP's own `_meta` decides instead.

### `SMSS_MCP_UI`

[MCPUtility.getValidMcpUI](../../src/prerna/reactor/agent/mcp/MCPUtility.java) sanitizes the object on every tool-call response and keeps only these keys:

| Key | Values | Notes |
| --- | --- | --- |
| `resourceURI` | String, portal path such as `"index.html"` or `"/"` | Opens the project's portal for the tool instead of the generic view. |
| `loadingMessage` | String | Shown while the tool runs. |
| `displayLocation` | `"inline"`, `"sidebar"`, `"hidden"` | Invalid values are dropped at runtime and rejected by `MakePixelMCP`. |
| `component` | Non-blank string | Native element for the call. Known names: `email-compose`, `email-draft`, `email-send`, `calendar-event`. Pages that do not know a name use the generic view. |
| `autoOpen` | Boolean (or `"true"` / `"false"`) | Open the tool view automatically. |

Tools with a `component` keep their `_meta` on calls even when they are `auto` (`SemossAgentHarness.restoreAskMetadataForParameterTools`).

## Keys the platform stamps

Do not set these in tool definitions. The platform writes them, and some override routing.

| Key | Set by | Used for |
| --- | --- | --- |
| `SMSS_ENGINE_ID`, `SMSS_ENGINE_NAME`, `SMSS_ENGINE_TYPE` | `InternalMCP.getMCPTools`, `RemoteMCP`, `Room` (`__room__` for the room toolbox) | Routing. A tool-level `SMSS_ENGINE_ID` overrides the engine's value in the room lookup and misroutes the call. |
| `SMSS_ORIGINAL_TOOL_NAME` | `Room.getToolJson` lookup | Real tool name behind the model-facing alias. Used to execute and to build deferred IDs. |
| `SMSS_TOOL_TITLE` | `SemossAgentHarness.persistPendingActions` | Display-only title on pending approval actions. Never executed. |
| `SMSS_MCP_GENERATOR` | `MCPUtility.stampGenerator`, `smssutil.gen_mcp` | Marks which generator owns a tool so regeneration can replace or prune it. |
| `SMSS_PROJECT_ID`, `SMSS_PROJECT_NAME` | Nothing (deprecated) | Still read as a fallback for `SMSS_ENGINE_ID`. Do not add new reads. |

## Support by MCP type

| Option | Pixel reactor `getMcpToolMetadata()` | `MakePixelMCP` / `MakeRoomPixelMCP` / `MakeUserPixelMCP` `mcpMetadata` | Python `@mcp_metadata` | Hand-edited JSON | `MakeEngineMCP` `mcpMetadata` | Remote MCP |
| --- | --- | --- | --- | --- | --- | --- |
| `SMSS_MCP_EXECUTION` | Yes | Yes (validated) | Yes (`execution` key) | Yes | Yes | No, forced `auto` |
| `SMSS_MCP_DEFERRED` | No | Yes, explicitly named reactors only | Yes (`deferred` key) | Yes, lost on regeneration | No | Not verified |
| `resourceURI`, `loadingMessage`, `displayLocation` | Yes | Yes | Yes | Yes | Yes | No, forced `{}` |
| `component`, `autoOpen` | Yes | Yes | Yes | Yes, lost on regeneration | Yes | No |

## Setting metadata

### Pixel reactors

A reactor can declare defaults by overriding [AbstractReactor.getMcpToolMetadata](../../src/prerna/reactor/AbstractReactor.java). The map is `Map<String, String>`. Execution and UI keys are copied into `_meta` by `asMcpTool()`; other keys, including `SMSS_MCP_DEFERRED`, are not.

```java
@Override
public Map<String, String> getMcpToolMetadata() {
	Map<String, String> meta = super.getMcpToolMetadata(); // auto + sidebar
	meta.put(MCPUtility.SMSS_MCP_EXECUTION, MCPUtility.MCPExecution.ASK.getValue());
	meta.put(MCPUtility.UI_LOADING_MESSAGE, "Sending email...");
	meta.put(MCPUtility.UI_COMPONENT, MCPUtility.COMPONENT_EMAIL_COMPOSE);
	return meta;
}
```

The default implementation returns a non-null map, so a full or package scan includes every compiled project reactor, not only those that override it.

`mcpMetadata` overrides per call. Entries match `reactor` by position, and the counts must match or the reactor throws ([PixelMCPToolBuilder](../../src/prerna/reactor/agent/mcp/PixelMCPToolBuilder.java)):

```
MakePixelMCP(
  project=["<projectId>"],
  reactor=["RunPolicy", "LoadPolicy"],
  mcpMetadata=[
    {"SMSS_MCP_EXECUTION": "ask", "SMSS_MCP_DEFERRED": true,
     "SMSS_MCP_UI": {"displayLocation": "sidebar", "loadingMessage": "Running policy..."}},
    {"SMSS_MCP_EXECUTION": "auto"}
  ]
);
```

Merge rules in `PixelMCPToolBuilder`:

- `SMSS_MCP_EXECUTION`: an omitted value keeps the reactor's declared value (`auto` if none). An invalid non-blank value throws. A blank value becomes `auto` with a warning.
- `SMSS_MCP_DEFERRED`: must be a boolean or the call throws. Only applied when `reactor` names the reactor; `package` and full scans never receive `mcpMetadata`.
- `SMSS_MCP_UI`: if supplied, it replaces the reactor's `resourceURI`, `loadingMessage`, and `displayLocation`. Supplying only `loadingMessage` drops the reactor's default `displayLocation: sidebar`. The reactor's `component` and `autoOpen` stay unless overridden. An invalid `displayLocation` throws.

`MakeRoomPixelMCP(roomId=[...], reactor=[...], mcpMetadata=[...])` and `MakeUserPixelMCP(filePath=[...], reactor=[...], mcpMetadata=[...], generator=[...])` use the same builder and rules.

`MakeEngineMCP(engine=[...], reactor=[...], mcpMetadata=[...])` accepts execution and UI only. An entry with `SMSS_MCP_UI` replaces the reactor's declared UI; without it the tool gets an empty UI map.

### Python

Decorate functions in `assets/py/mcp_driver.py` with `mcp_metadata` from [smssutil.py](../../py/smssutil.py), then run `MakePythonMCP(project=["<projectId>"])`:

```python
from smssutil import mcp_metadata

@mcp_metadata({
    "execution": "ask",
    "deferred": True,
    "loadingMessage": "Fetching price...",
    "displayLocation": "sidebar",
    "resourceURI": "index.html",
    "component": "email-compose",
    "autoOpen": True,
})
def get_stock_price(symbol: str) -> float:
    """Return the latest price for a ticker.

    Args:
        symbol (str): Ticker symbol.
    """
```

- Use a literal dict. If the driver cannot be imported, the generator falls back to AST parsing, which reads only literals.
- `execution` matches exactly: anything other than `"auto"`, `"yesno"`, or `"disabled"` becomes `"ask"`, including `"Disabled"`. A function without the decorator is `ask`.
- The dict is flat. `execution` and `deferred` become `SMSS_MCP_EXECUTION` and `SMSS_MCP_DEFERRED`; `loadingMessage`, `resourceURI`, `displayLocation`, `component`, and `autoOpen` go into `SMSS_MCP_UI`. Other keys are dropped.
- `deferred` must be the boolean `True`; the string `"true"` is ignored. `component` is trimmed and dropped when blank. `autoOpen` accepts a boolean or `"true"` / `"false"`.
- `@mcp_execution("ask")` still works but is deprecated.
- Every top-level function whose name does not start with `_` becomes a tool, and every argument is marked required. Argument descriptions come only from a Google-style `Args:` section with `name (type): description` lines.

### Hand-edited JSON and regeneration

The runtime reads `_meta` from `pixel_mcp.json` and `py_mcp.json` as written, so hand edits take effect on the next model call. Regeneration rules ([MCPUtility.mergeGeneratedTools](../../src/prerna/reactor/agent/mcp/MCPUtility.java)):

- A generated tool replaces any existing tool with the same name, so a hand-added key on a generated tool is lost on the next `MakePixelMCP` or `MakePythonMCP`.
- A hand-written tool survives when its name does not collide and it has no `SMSS_MCP_GENERATOR` stamp from that generator. Leave `SMSS_MCP_GENERATOR` off hand-written tools.
- `MakePixelMCP` prunes tools it no longer generates only on a full scan. `MakeRoomPixelMCP` and `MakeUserPixelMCP` always prune their own stamp.

## Runtime behavior

| | `RunAgent` (native `semoss` harness) | `AskRoom` / plain room chat |
| --- | --- | --- |
| `disabled` | Hidden from the model | Hidden for room and workspace MCP tools. Explicit `paramValues.tools` are not filtered. |
| `ask` | [HarnessToolExecutor](../../src/prerna/reactor/agent/runtime/HarnessToolExecutor.java) runs the batch's non-ask tools, then pauses with an `AGENT_RUN_ACTION` row per ask tool. [AgentToolDecisionHandler](../../src/prerna/reactor/agent/mcp/AgentToolDecisionHandler.java) runs the tool on approve or edit. | The server runs nothing. `_meta.SMSS_MCP_EXECUTION` is returned on the tool call and the client decides whether to ask. |
| `yesno` | Same as `ask` (`MCPUtility.isAskLikeExecution`) | Same as `ask`; the frontend renders a dedicated approve/reject control instead of the generic ask card. |
| `auto` | Runs immediately | Returned to the client; the client runs it |
| Deferred | Hidden until loaded with `SearchTools` / `LoadTools` | Sent eagerly |
| `SMSS_MCP_UI` | Sanitized and attached to tool-call metadata | Same |

See [run lifecycle](agent_runs.md) for approval states and [the harness](semoss_harness.md#tools-and-execution-policy) for the built-in tool groups.

## Pitfalls

- Use lowercase execution values in hand-written JSON. The hide filter is case-sensitive.
- Use a boolean for `SMSS_MCP_DEFERRED`. Pixel string `"true"` throws; JSON string `"true"` is silently ignored.
- Do not set `SMSS_ENGINE_ID` or `SMSS_ORIGINAL_TOOL_NAME` on a tool. They control routing.
- `execution` placed inside `SMSS_MCP_UI` is ignored. It belongs at the top level of `_meta`.
- `disabled` and deferred are not permissions. Use engine and project access checks for that.
