# Citations and uncertainty

## Make claims traceable

Put the source next to the fact it supports. Use a message or file link only when
the context or tool result provides the actual URL. Keep its exact destination and
use a descriptive label. Do not invent link routes or claim an excluded source was read.

When no link is available, use a clear source label:

- `Email from the sender, October 2, subject "Review request"`.
- `brief.docx, "Recommendations" section`.
- `budget.xlsx, Forecast sheet, rows 12–18`.
- `meeting-notes.md, lines 24–31`.

Use the actual author, date, filename, and location from the source. Invented page
numbers, timestamps, quotes, and IDs are not citations. A text extraction's line
numbers identify the extraction, not automatically the original document's pages.

For a calculation, identify the input source, relevant rows or values, units, and
the method. For a conclusion combining several sources, identify the combination
as your analysis rather than attributing it to a single sender.

## Separate fact, inference, and proposal

| Kind | How to phrase it |
| --- | --- |
| Explicit fact | State it with the supporting source |
| Conflicting evidence | Identify the disagreement and what would resolve it |
| Reasonable inference | Explain what evidence suggests it and qualify it |
| Missing information | State the specific information you could not find or read |
| Proposal | Label it as a proposed action, wording, date, or owner |
| Partial review | Name the pages, sheets, slides, or excerpt actually inspected |

"I did not find a deadline in the included messages" is narrower and more accurate
than "there is no deadline." "The document's extracted text supports this" does
not establish that its charts or scanned pages agree.

For quotations, preserve the wording and author and keep the quote proportionate
to the task. For paraphrases, retain qualifications such as tentative, conditional,
or pending. Do not convert a suggestion into a commitment through stronger wording.

## Match the destination

Chat answers can include descriptive Markdown links and concise source labels.
`ComposeEmail.message` is plain text: keep source attribution natural and do not
insert Markdown syntax. Draft claims must still be supported, even if a formal
citation would be inappropriate for the recipient.

Finish with the requested answer, the important supporting evidence, and material
uncertainty. Avoid overwhelming a short reply with a research log or a blanket
disclaimer. Do not claim certainty merely because a tool returned successfully.
